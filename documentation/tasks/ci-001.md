## Цель

На каждый push в `main` и каждый pull request GitHub Actions проверяет
конфигурации, ищет секреты и **разворачивает всё решение с нуля на
настоящей Ubuntu 24.04 через kubeadm** тем же `sudo ./deploy.sh`, который
запустит эксперт. Потом проверяет идемпотентность повторным запуском и
прогоняет `scripts/verify.sh`. Так воспроизводимость подтверждается
автоматически, а не только нашими ручными прогонами.

## Scope

### Входит

- workflow `.github/workflows/ci.yml` с тремя jobs:
  - `lint` — yamllint, ansible-lint (профиль `production`), shellcheck,
    `kubectl kustomize` + kubeconform для каждого каталога `deploy/*`;
  - `secrets` — gitleaks по всей истории git;
  - `e2e` — подготовка раннера → `deploy.sh` → повторный `deploy.sh`
    (падает, если `changed` ≠ 0) → `verify.sh`; при падении —
    диагностика в артефакт;
- `ci/prepare-runner.sh` — приводит раннер к «чистой Ubuntu 24.04»;
- `scripts/verify.sh` — единая проверка решения (используется и в CI, и
  экспертом: `make verify`);
- `deploy.sh` всегда использует Ansible из репозитория Ubuntu;
- конфиги `.yamllint`, `.ansible-lint`.

### Не входит

- развёртывание на наш стенд (см. «CD» ниже);
- публикация образов: собственных образов нет.

## Технические требования

| Инструмент | Версия |
|---|---|
| Раннер | `ubuntu-24.04` (GitHub-hosted) |
| actions/checkout, setup-python, upload-artifact | v7 |
| yamllint / ansible-lint | 1.38.0 / 26.9.0 |
| kubeconform | v0.8.0 (+ схемы CRD из datreeio/CRDs-catalog) |
| gitleaks | 8.30.1 |

**CD.** Решение — это инфраструктурный код, а не сервис с постоянным
окружением. Роль CD выполняет job `e2e`: каждый коммит в `main`
автоматически разворачивается в эфемерное окружение (чистая Ubuntu 24.04 +
kubeadm) и проверяется smoke-тестами. Автодеплой на наш стенд не делаем:
VM стоит на личном ПК за NAT и VPN без публичного адреса, а self-hosted
runner на личной машине, подключённый к публичному репозиторию, — риск
безопасности (чужой pull request может выполнить код на машине).

## Артефакты

| Артефакт | Назначение |
|---|---|
| `.github/workflows/ci.yml` | Pipeline |
| `ci/prepare-runner.sh` | Подготовка раннера |
| `scripts/verify.sh` | Проверка решения |
| `.yamllint`, `.ansible-lint` | Конфигурация линтеров |

## Критерии приёмки

- [x] Локально на VM: yamllint `--strict`, ansible-lint `production`,
      shellcheck — без замечаний.
- [x] `verify.sh` на VM проходит все проверки.
- [ ] В GitHub Actions зелёные `lint`, `secrets`, `e2e`.
- [ ] В `e2e` повторный `deploy.sh` даёт `changed=0`.
- [ ] Бейдж статуса CI — в корневом README (DOCS-002).

## Проверка

Вкладка Actions репозитория: последний запуск workflow `CI` по `main`.

## Результат закрытия

Заполняется после первого зелёного запуска в GitHub Actions.
