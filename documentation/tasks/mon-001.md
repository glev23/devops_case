## Цель

Prometheus собирает метрики кластера, узла и приложения. Все targets в
состоянии `UP`, PromQL-запрос возвращает реальные данные. Эксперт проверяет
это одной командой `make verify`.

## Scope

### Входит

- Helm-чарт kube-prometheus-stack с values из репозитория: Prometheus
  Operator, Prometheus, Alertmanager, node-exporter, kube-state-metrics,
  Grafana с дашбордами из чарта;
- пароль admin Grafana — случайный, создаётся один раз в Secret
  `monitoring/grafana-admin`, пароль чарта по умолчанию не используется;
- метрики control plane kubeadm (controller-manager, scheduler, etcd,
  kube-proxy) слушают стабильный адрес узла, чтобы их targets были `UP`;
- sidecar `nginx-prometheus-exporter` + ServiceMonitor для приложения;
- раздел «Мониторинг» в `scripts/verify.sh`.

### Не входит

- метрики Envoy (запросы, коды, latency по маршрутам) и свой дашборд — MON-002;
- доступ к Grafana/Prometheus через Gateway и datasource Loki — GRAF-001;
- постоянное хранилище метрик (PV) — см. ограничения.

## Критерии приёмки

- [x] Все targets `UP`: `count(up == 0) = 0`.
- [x] Targets на месте: apiserver, kubelet, node-exporter, kube-state-metrics,
      coredns, kube-controller-manager, kube-scheduler, kube-etcd, kube-proxy,
      hello (nginx).
- [x] PromQL `sum(nginx_http_requests_total)` возвращает значение > 0.
- [x] Grafana не принимает пароль по умолчанию, принимает сгенерированный.
- [x] Повторный `deploy.sh` → `changed=0`.
- [x] CI `e2e` зелёный.

## Проверка

```bash
make verify
# Prometheus UI: http://localhost:9090 → Status → Targets, Graph
kubectl -n monitoring port-forward svc/kps-prometheus 9090:9090
# Пароль Grafana:
kubectl -n monitoring get secret grafana-admin -o jsonpath='{.data.admin-password}' | base64 -d
```
