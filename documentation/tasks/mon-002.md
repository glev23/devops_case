## Цель

HTTP-метрики трафика через Gateway (запросы, коды ответов, latency) по
каждому маршруту — в Prometheus и на дашборде Grafana из репозитория, рядом
с CPU/RAM приложения и логами ошибок из Loki. Алерты на ключевые отказы.
Фоновая нагрузка, чтобы графики были живыми сразу после установки.

## Что реализовано

| Часть | Как |
|---|---|
| Метрики прокси Envoy | `PodMonitor monitoring/envoy-proxy` → `/stats/prometheus` (порт 19001), каждые 15 с; метка `route="<ns>/<route>#<правило>"` из `envoy_cluster_name` |
| Метрики контроллера | `ServiceMonitor monitoring/envoy-gateway` |
| Recording rules | `route:envoy_upstream_rq:rate5m`, `route:envoy_upstream_rq_5xx:rate5m` |
| Алерты (`PrometheusRule devops-case`) | `DemoAppTargetDown`, `DemoAppNoReplicas`, `GatewayHigh5xxRatio` (>10% за 5 мин), `GatewayHighLatencyP95` (>500 мс), `GatewayProxyDown`, `FluentdNotReady`, `LokiDown` |
| Дашборд | «DevOps case / Gateway и приложение» (`uid devops-case-gateway`), JSON в `deploy/monitoring/dashboards/`, загружается sidecar Grafana из ConfigMap с `grafana_dashboard: "1"` |
| Фоновая нагрузка | `Deployment demo/loadgen` (curl, non-root): ~4 запроса/с через Gateway по `/`, `/canary`, `/v2`, HTTPS, изредка `/error` (500) и несуществующий путь (404) |

**Панели дашборда:** запросы/с через Gateway, доля 5xx, p95, поды
приложения UP; запросы/с по маршрутам HTTPRoute; ответы по классам кодов;
p50/p95/p99 upstream; деление трафика v1/v2 (nginx-exporter); HTTP и HTTPS
listener; CPU и память подов `demo`; логи nginx с `status >= 400` из Loki.

## Критерии приёмки

- [x] В Prometheus есть `envoy_cluster_upstream_rq_total` по маршрутам `demo/hello#0..2`.
- [x] Группы правил `devops-case.app/gateway/logging` загружены.
- [x] Дашборд есть в Grafana; каждый запрос панелей возвращает данные.
- [x] При фоновой нагрузке собственные алерты не срабатывают (доля 5xx ~1%).
- [x] Повторный `deploy.sh` → `changed=0`.
- [x] CI `e2e` зелёный.

**Отклонения от постановки:**
- В `metricRelabelings` PodMonitor явно указан `action: replace` (значение по
  умолчанию): иначе `kubectl apply` каждый раз сообщал `configured`.
- Ответ `/api/v1/rules` со всеми правилами чарта превышает лимит длины
  аргумента командной строки — `verify.sh` передаёт его в Python через stdin.
- Деление трафика v1/v2 на графике берётся из метрик nginx: Envoy считает
  взвешенные backend одного правила одним upstream-кластером.

**Особенность стенда:** на VM не синхронизируется время — UDP 123 (NTP) не
проходит через Hyper-V NAT и WireGuard; алерт `NodeClockNotSynchronising`
это корректно показывает. На обычной Ubuntu и в CI не воспроизводится.
