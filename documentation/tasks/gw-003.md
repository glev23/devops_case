## Цель

Показать политики Envoy Gateway поверх Gateway API — то, что в
продакшене отличает «маршрут» от «надёжного входа»: таймауты, ретраи на
сетевые сбои, circuit breaker и rate limiting с ответом 429. Заодно
выделить `/error` в отдельное правило маршрута, чтобы демонстрационные 500
не портили SLI основного маршрута (нужно для SLO-001 и анализа canary в
ROLLOUT-001).

## Scope

### Входит

- `HTTPRoute demo/hello`: отдельное правило `Exact /error` → `hello`
  (сейчас `/error` попадает в правило `/`);
- `BackendTrafficPolicy` на `HTTPRoute demo/hello`:
  - таймаут запроса к backend (например, 5 с);
  - ретраи только на сетевые сбои (`connect-failure`, `reset`, `retriable-status-codes` не
    включаем — иначе ретраи маскируют 5xx и ломают анализ canary);
  - circuit breaker (лимиты соединений и запросов к backend);
- rate limiting: отдельный маршрут `/limited` (или правило), local rate
  limit, например 5 запросов/с на клиента → сверх лимита `429`;
- `ClientTrafficPolicy` на Gateway: таймауты соединения клиента,
  доверие к `X-Forwarded-For` (1 hop);
- проверки в `verify.sh`; обновление описания правил в дашборде
  (индексы `route` `#N` изменятся).

### Не входит

- глобальный rate limit через Redis (лишний компонент на одном узле);
- аутентификация (SEC-001).

## Технические требования

- Envoy Gateway v1.9.2: `gateway.envoyproxy.io/v1alpha1`
  `BackendTrafficPolicy`, `ClientTrafficPolicy`. ⚠️ Проверить по
  документации v1.9, поддерживается ли таргетинг политики на отдельное
  правило маршрута (`sectionName`); если нет — rate limit на отдельный
  `HTTPRoute`.
- Rate limit не должен задевать `loadgen` (~4 запроса/с) и проверки
  `verify.sh` (100 запросов к `/canary` подряд) — поэтому только на `/limited`.
- Все значения по умолчанию в списках указывать явно (идемпотентность
  `kubectl apply`, см. GW-001).

## Артефакты

| Артефакт | Назначение |

| `deploy/gateway/client-policy.yaml` | `ClientTrafficPolicy` |

| `scripts/verify.sh` | Проверки |

## Критерии приёмки

- [ ] Политики в статусе `Accepted`.
- [ ] 30 быстрых запросов к `/limited` → есть ответы `429`, первые — `200`.
- [ ] `/error` — отдельное правило; 5xx правила `/` ≈ 0 при фоновой нагрузке.
- [ ] Остальные проверки `verify.sh` не деградировали (canary 80/20 без 429).
- [ ] Повторный `deploy.sh` → `changed=0`; CI `e2e` зелёный.

## Проверка

```bash
for i in $(seq 30); do curl -s -o /dev/null -w '%{http_code}\n' http://<IP>:30080/limited; done | sort | uniq -c
kubectl get backendtrafficpolicy,clienttrafficpolicy -A
make verify
```
