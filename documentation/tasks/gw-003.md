## Цель

Показать политики Envoy Gateway поверх Gateway API — то, что в
продакшене отличает «маршрут» от «надёжного входа»: таймауты, ретраи на
сетевые сбои, circuit breaker и rate limiting с ответом 429. Заодно
выделить `/error` в отдельное правило маршрута, чтобы демонстрационные 500
не портили SLI основного маршрута (нужно для SLO-001 и анализа canary в
ROLLOUT-001).

## Scope

### Входит

- `HTTPRoute demo/hello`: отдельное правило `Exact /error` → `hello`
  (раньше `/error` попадал в правило `/`);
- `BackendTrafficPolicy` на `HTTPRoute demo/hello`:
  - таймаут запроса к backend (например, 5 с);
  - ретраи только на сетевые сбои (`connect-failure`, `reset`, `retriable-status-codes` не
    включаем — иначе ретраи маскируют 5xx и ломают анализ canary);
  - circuit breaker (лимиты соединений и запросов к backend);
- rate limiting: правило `/limited` (URL rewrite → `/`), local rate limit
  5 запросов/с на путь `/limited` через `clientSelectors.path` → сверх
  лимита `429`;
- `ClientTrafficPolicy` на Gateway: таймауты клиента, лимит соединений,
  отклонение заголовков с подчёркиванием, сохранение `X-Request-Id`
  клиента; `X-Forwarded-For` от клиента не доверяем (Gateway — первая
  точка входа);
- проверки в `verify.sh`; обновление описания правил в дашборде
  (индексы `route` `#N` изменятся).

### Не входит

- глобальный rate limit через Redis (лишний компонент на одном узле);
- аутентификация (SEC-001).

## Технические требования

- Envoy Gateway v1.9.2: `gateway.envoyproxy.io/v1alpha1`
  `BackendTrafficPolicy`, `ClientTrafficPolicy`. ⚠️ Проверить по
  документации v1.9, поддерживается ли таргетинг политики на отдельное
  правило маршрута (`sectionName`); если нет — rate limit на отдельный
  `HTTPRoute`.
- Rate limit не должен задевать `loadgen` (~4 запроса/с) и проверки
  `verify.sh` (100 запросов к `/canary` подряд) — поэтому только на `/limited`.
- Все значения по умолчанию в списках указывать явно (идемпотентность
  `kubectl apply`, см. GW-001).

## Критерии приёмки

- [x] Политики в статусе `Accepted`.
- [x] 30 быстрых запросов к `/limited` → есть ответы `429`, первые — `200`.
- [x] `/error` — отдельное правило; 5xx правила `/` ≈ 0 при фоновой нагрузке.
- [x] Остальные проверки `verify.sh` не деградировали (canary 80/20 без 429).
- [x] Повторный `deploy.sh` → `changed=0`; CI `e2e` зелёный.

## Проверка

```bash
for i in $(seq 30); do curl -s -o /dev/null -w '%{http_code}\n' http://<IP>:30080/limited; done | sort | uniq -c
kubectl get backendtrafficpolicy,clienttrafficpolicy -A
make verify
```

`deploy/gateway/client-policy.yaml` (`ClientTrafficPolicy`), правила `#3 /error`
и `#4 /limited` в `deploy/app/httproute.yaml`, описание правил на дашборде,
раздел «Политики трафика Gateway» в `scripts/verify.sh`.

| Проверка | Результат |
|---|---|
| Политики | `BackendTrafficPolicy demo/hello`, `ClientTrafficPolicy gateway/main` — `Accepted` |
| Rate limit | 30 запросов к `/limited` → `200×5 429×25` (VM и CI); заголовок `x-ratelimit-limit: 5` |
| Не задевает остальной трафик | `/canary` 100 запросов → 79/21, без 429 |
| `/error` | отдельное правило (`#3`), ответ 500 без `X-Backend` правила `/` |
| Заголовки | `x_user_id: 42` → 400, `x-user-id: 42` → 200 |
| `X-Request-Id` | клиентский ID (`my-own-id-12345`, `loadgen-6112`) доходит до лога nginx — раньше Envoy генерировал свой |
| Повтор `deploy.sh` | `changed=0` |
| GitHub Actions | [run 36874578413](https://github.com/glev23/devops_case/actions/runs/36874578413): lint, secrets, e2e — зелёные; e2e 6 мин 22 с |

**Отклонения от постановки:**
- Rate limit — правилом внутри общего маршрута (`clientSelectors.path`), а не
  отдельным `HTTPRoute`: селектор по пути в Envoy Gateway 1.9 есть.
- В селекторе пути явно указан `invert: false` (значение по умолчанию) —
  иначе `kubectl apply` каждый раз сообщал `configured`.
- Из `ClientTrafficPolicy` убраны `requestHeadersReceivedTimeout` и
  `tlsHandshakeTimeout`: кластер их принимает, но схемы CRDs-catalog, по
  которым kubeconform валидирует в CI, их ещё не знают (первый запуск CI
  упал на линте). `requestReceivedTimeout` ограничивает приём всего запроса.
- Ретраи — только на `connect-failure`, `reset`, `refused-stream`: ретраи на
  5xx скрыли бы ошибки плохого релиза от анализа canary (ROLLOUT-001).
