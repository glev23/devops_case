## Цель

Автоматизация писалась вместе с каждой задачей (одна команда `sudo ./deploy.sh`,
идемпотентность с проверкой в CI, `make verify`). Здесь — добить остаток:
удаление кластера для переустановки с нуля и установка на удалённый узел.

## Что сделано по ходу проекта (итог)

| Требование кейса | Как закрыто |
|---|---|
| Одна команда | `sudo ./deploy.sh` (или `sudo make deploy`) — от чистой Ubuntu 24.04 до работающего решения; Ansible ставится сам из репозитория Ubuntu |
| Без ручного создания ресурсов | всё — Ansible (узел, kubeadm, Helm-чарты, секреты) + Argo CD / `kubectl apply -k` (манифесты `deploy/*`) |
| Повторный запуск не ломает систему | `changed=0` на повторе — проверяется в CI на каждый push (`--diff` при нарушении) |
| Управление зависимостями | все версии — `ansible/group_vars/all.yml`; пакеты `apt-mark hold`; бинарники и образы плагинов — по SHA-256/digest |
| Проверка результата | `make verify` (~50 проверок), `make demo` |

## Scope этой задачи

### Входит

- `./destroy.sh` / `sudo make destroy` (`ansible/destroy.yml`): `kubeadm reset`,
  удаление конфигураций CNI и Calico, kubeconfig, состояния Fluentd,
  интерфейсов Calico, правил iptables Kubernetes/Calico (точечно), перезапуск
  containerd; с подтверждением (или `--yes`); пакеты и образы остаются;
- установка на удалённый узел: в `inventory.ini` — хост с SSH; play
  «Repository files on the node» копирует `deploy/`, `helm-values/`,
  `scripts/`, `Makefile` в `/opt/devops-case`, роли используют их там;
- `make` ставится на узел (чистая Ubuntu его не содержит);
- shellcheck `destroy.sh` в CI.

### Не входит

- многоузловой кластер (D-02).

## Критерии приёмки

- [x] `destroy.sh` на работающем кластере — без ошибок; после него нет
      `/etc/kubernetes`, правил iptables KUBE-/cali-, запущенных контейнеров.
- [x] После `destroy.sh` — `deploy.sh` ставит всё заново, повтор `changed=0`,
      `verify.sh` зелёный.
- [x] Удалённый режим: playbook по SSH копирует файлы и применяет решение;
      повтор `changed=0`.
- [x] ansible-lint `production`, shellcheck — без замечаний; CI зелёный.

| Удалённый режим (SSH к узлу как к удалённому хосту, `ansible_host=127.0.0.1`) | первый прогон — `changed=1` (копирование файлов в `/opt/devops-case`), повтор — `changed=0` |

**Найдено и исправлено:**
- **`deploy.sh` после очистки узла падал**: роль kubeadm писала конфиг в
  `/etc/kubernetes`, рассчитывая, что каталог создал пакет kubelet при
  установке. После удаления каталога (пакеты остаются) — «Destination
  directory does not exist». Роль теперь создаёт каталоги сама.
- **Calico монтирует cgroup2 в `/var/run/calico/cgroup`** — без
  размонтирования каталог не удаляется; destroy размонтирует.
- `kubeadm reset` на узле с запущенными подами может идти ~2 мин (ретраи
  удаления узла из etcd) — нормально, указано в README.
