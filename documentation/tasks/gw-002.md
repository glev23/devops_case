## Цель

Показать расширенные возможности Gateway API стандартными ресурсами, с
проверкой каждой в `make verify`: несколько маршрутов, маршрутизацию по
hostname и path, несколько backend, traffic splitting, изменение запроса и
ответа, TLS.

## Что реализовано

| Возможность | Как | Проверка |
|---|---|---|
| Маршрутизация по hostname | `grafana.devops.test`, `prometheus.devops.test` (GRAF-001); остальные Host → приложение | `curl -H "Host: …"` |
| Маршрутизация по path + URL rewrite | `/v2/*` → `hello-v2`, префикс заменяется на `/` (`URLRewrite`, `ReplacePrefixMatch`) | `curl :30080/v2` → `… from hello-v2-…` |
| Несколько backend + traffic splitting | `/canary/*` → `hello` вес 80, `hello-v2` вес 20 | 100 запросов → ~80/20 |
| Изменение ответа | `ResponseHeaderModifier`: `X-Backend: v1/v2`, `X-Route: canary` | заголовки ответа |
| TLS | HTTPS-listener `:443` (NodePort 30443), `tls.mode: Terminate`, сертификат `*.devops.test` от cert-manager | `curl --cacert ca.crt` — строгая проверка |
| Несколько маршрутов | 3 `HTTPRoute` (`demo/hello`, `monitoring/grafana`, `monitoring/prometheus`) на 2 listener | `attachedRoutes=3` на каждом |
| Ограничение доступа к Gateway | `allowedRoutes` — только namespace с меткой `gateway-access: "true"` | маршрут из другого namespace не примется |
| Ошибки для метрик | `/error` → 500 (nginx) | `curl :30080/error` → 500 |

**TLS-цепочка.** `ClusterIssuer selfsigned` → `Certificate devops-ca`
(`isCA`, 10 лет) → `ClusterIssuer devops-ca` → `Certificate devops-test-tls`
(`devops.test`, `*.devops.test`, 90 дней, автопродление за 15 дней). Свой CA,
а не просто самоподписанный сертификат: клиент проверяет сертификат
по-настоящему, без `-k`. Ключи выпускает cert-manager в кластере, в
репозитории их нет.

**hello-v2** собирается из той же Kustomize-базы (`deploy/app/base` →
overlay `deploy/app/v2`: `nameSuffix: -v2`, метка `app.kubernetes.io/name:
hello-v2`, 1 реплика). У v1 имена и селекторы не менялись: селектор
Deployment неизменяем, и `apply` на существующем кластере упал бы.

## Критерии приёмки

- [x] `/v2` → `hello-v2`, заголовок `X-Backend: v2`; `/` → `X-Backend: v1`.
- [x] `/canary`: из 100 запросов ~80 на v1 и ~20 на v2.
- [x] `/error` → 500.
- [x] `https://hello.devops.test:30443/` проходит проверку по CA кластера;
      без CA — отказ (`UNTRUSTED_ROOT`).
- [x] Оба listener `Programmed`, к каждому привязано 3 маршрута.
- [x] Повторный `deploy.sh` → `changed=0`.
- [x] CI `e2e` зелёный.

## Проверка

```bash
make verify
IP=<IP узла>
curl -si http://$IP:30080/v2 | grep -iE 'x-backend|hello'
for i in $(seq 20); do curl -s http://$IP:30080/canary; done | sort | uniq -c
kubectl -n gateway get secret devops-test-tls -o jsonpath='{.data.ca\.crt}' | base64 -d > ca.crt
curl --cacert ca.crt --resolve hello.devops.test:30443:$IP https://hello.devops.test:30443/
```
