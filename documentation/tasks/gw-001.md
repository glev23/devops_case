## Цель

Запрос снаружи кластера `curl http://<IP узла>:30080/` проходит через
Gateway API (Envoy Gateway) и возвращает `Hello World! from <pod>`.
Всё ставится тем же `sudo ./deploy.sh`.

## Scope

### Входит

- Helm-чарт Envoy Gateway `v1.9.2` (`oci://docker.io/envoyproxy/gateway-helm`)
  в namespace `envoy-gateway-system`; CRD Gateway API приходят с чартом;
- `EnvoyProxy` — прокси публикуется Service типа NodePort с фиксированным
  портом `30080`;
- `GatewayClass` `eg` → `EnvoyProxy`;
- `Gateway` `main` (namespace `gateway`), listener HTTP :80, маршруты
  разрешены из namespace с меткой `gateway-access: "true"`;
- `HTTPRoute` `hello` (namespace `demo`) → Service `hello:80`;
- проверка в `verify.sh`: статусы `Accepted`/`Programmed` и `curl` через
  NodePort.

### Не входит

- host/path-маршрутизация, несколько backend, веса, TLS (GW-002);
- метрики Envoy в Prometheus (MON-002).

## Критерии приёмки

- [x] `GatewayClass eg` — `Accepted=True`; `Gateway main` — `Programmed=True`;
      `HTTPRoute hello` — `Accepted=True`, `ResolvedRefs=True`.
- [x] С узла: `curl http://<IP узла>:30080/` → `Hello World! from hello-…`.
- [x] С ПК команды (вне VM): тот же `curl` по IP VM.
- [x] В access-логе nginx у запроса через Gateway есть `x_forwarded_for`.
- [x] Повторный `deploy.sh` → `changed=0`.
- [x] CI `e2e` зелёный.

## Проверка

```bash
kubectl get gatewayclass,gateway -A
kubectl -n demo get httproute hello -o wide
curl -s http://<IP узла>:30080/
make verify
```

| Проверка | Результат |
|---|---|
| `kubectl get gatewayclass,gateway -A` | `eg` Accepted=True; `gateway/main` Programmed=True, ADDRESS `10.200.0.10` |
| Service прокси | `envoy-gateway-main-…` NodePort `80:30080/TCP` |
| `verify.sh` на VM | все проверки пройдены, включая HTTPRoute Accepted/ResolvedRefs |
| `curl http://<IP VM>:30080/` с Windows-ПК | `Hello World! from hello-…-lpksr` / `…-dtwrn` — обе реплики; `/nope` → 404 |
| Лог nginx | у запроса через Gateway заполнен `x_forwarded_for` (Envoy) |
| Повтор `deploy.sh` | `changed=0` |
| GitHub Actions | run [36774899791](https://github.com/glev23/devops_case/actions/runs/36774899791): lint, secrets, e2e — зелёные; e2e 3 мин 31 с |

**Отклонения от постановки:**
- В `HTTPRoute` явно указаны значения по умолчанию (`group`, `kind`,
  `weight`): без них `kubectl apply` на CRD каждый раз сообщал `configured`,
  и повторный прогон давал `changed=1`.
- Первый запуск CI упал: на раннере через apt стоит `kubectl` 1.37, а apt
  не понижает версию без разрешения. В роли добавлен `allow_downgrade`
  (закреплённая версия — источник правды), в `prepare-runner.sh` пакет
  удаляется.
