## Цель

Запрос снаружи кластера `curl http://<IP узла>:30080/` проходит через
Gateway API (Envoy Gateway) и возвращает `Hello World! from <pod>`.
Всё ставится тем же `sudo ./deploy.sh`.

## Scope

### Входит

- Helm-чарт Envoy Gateway `v1.9.2` (`oci://docker.io/envoyproxy/gateway-helm`)
  в namespace `envoy-gateway-system`; CRD Gateway API приходят с чартом;
- `EnvoyProxy` — прокси публикуется Service типа NodePort с фиксированным
  портом `30080`;
- `GatewayClass` `eg` → `EnvoyProxy`;
- `Gateway` `main` (namespace `gateway`), listener HTTP :80, маршруты
  разрешены из namespace с меткой `gateway-access: "true"`;
- `HTTPRoute` `hello` (namespace `demo`) → Service `hello:80`;
- проверка в `verify.sh`: статусы `Accepted`/`Programmed` и `curl` через
  NodePort.

### Не входит

- host/path-маршрутизация, несколько backend, веса, TLS (GW-002);
- метрики Envoy в Prometheus (MON-002).

## Критерии приёмки

- [ ] `GatewayClass eg` — `Accepted=True`; `Gateway main` — `Programmed=True`;
      `HTTPRoute hello` — `Accepted=True`, `ResolvedRefs=True`.
- [ ] С узла: `curl http://<IP узла>:30080/` → `Hello World! from hello-…`.
- [ ] С ПК команды (вне VM): тот же `curl` по IP VM.
- [ ] В access-логе nginx у запроса через Gateway есть `x_forwarded_for`.
- [ ] Повторный `deploy.sh` → `changed=0`.
- [ ] CI `e2e` зелёный.

## Проверка

```bash
kubectl get gatewayclass,gateway -A
kubectl -n demo get httproute hello -o wide
curl -s http://<IP узла>:30080/
make verify
```
