## Цель

Fluentd собирает access- и error-логи приложения (и всех остальных
контейнеров) и отправляет их в Loki. После обращения к приложению запись
именно об этом запросе находится в Loki по уникальной метке; эксперт
проверяет это одной командой `make verify`.

## Scope

### Входит

- Loki (Helm-чарт `grafana/loki`) в режиме single binary, хранение в
  файловой системе;
- Fluentd DaemonSet (официальный образ `grafana/fluent-plugin-loki`):
  чтение `/var/log/containers/*.log` в формате CRI, метки
  `namespace`/`pod`/`container`/`stream`, разбор JSON access-лога nginx в
  поля, буфер на диске узла;
- раздел «Логирование» в `scripts/verify.sh`: запрос с меткой через Gateway
  → поиск в Loki через LogQL.

### Не входит

- datasource Loki и просмотр логов в Grafana (GRAF-001);
- алерты по логам.

## Технические требования

| Компонент | Версия |
|---|---|
| Loki | 3.6.11 (чарт `grafana/loki` 7.3.0) |
| Fluentd | 1.19.0 в образе `grafana/fluent-plugin-loki:3.7.8` (плагин `out_loki`) |

**Почему Fluentd, а не Filebeat.** Filebeat не умеет писать в Loki, а
Elasticsearch/OpenSearch (JVM, 2+ ГБ RAM) тесно на 8 ГБ рядом с Prometheus
(architecture.md, D-06). Fluent Bit не берём: кейс называет именно Fluentd.

## Критерии приёмки

- [x] Fluentd DaemonSet готов, в его логах нет ошибок разбора.
- [x] Запрос `curl http://<IP>:30080/?trace=<uuid>` находится в Loki по
      LogQL `{namespace="demo",container="nginx"} |= "<uuid>" | json | status="200"`.
- [x] Строка в Loki — разобранный JSON (uri, status, request_id, x_forwarded_for).
- [x] Собираются логи всех namespace (централизованное хранение).
- [x] Повторный `deploy.sh` → `changed=0`.
- [x] CI `e2e` зелёный.

## Проверка

```bash
make verify
# Вручную: запрос с меткой и поиск в Loki
curl -s "http://<IP узла>:30080/?trace=my-test-1"
kubectl run lq --rm -i --restart=Never --image=curlimages/curl:8.16.0 -- \
  curl -s -G http://loki.logging:3100/loki/api/v1/query_range \
  --data-urlencode 'since=10m' \
  --data-urlencode 'query={namespace="demo",container="nginx"} |= "my-test-1"'
```

**Отклонения от постановки:**
- Без PVC чарт Loki ничего не монтирует в `/var/loki`, а rootfs пода
  read-only. Данные вынесены в явный emptyDir (`singleBinary.extraVolumes`).
- Найден побочный эффект: при запуске без `$HOME` (systemd-run) Helm
  складывал кэш в каталог репозитория. `deploy.sh` теперь выставляет `HOME`,
  каталоги добавлены в `.gitignore`.
