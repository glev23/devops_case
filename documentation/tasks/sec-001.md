## Цель

Закрыть известные слабые места: Prometheus UI без пароля через Gateway,
отсутствие сетевой изоляции приложения и защиты от одновременного
выключения реплик. Каждая мера проверяема.

## Scope

### Входит

- **Basic auth на Prometheus** через `SecurityPolicy` Envoy Gateway на
  `HTTPRoute monitoring/prometheus`. Пароль генерируется Ansible один раз
  (как у Grafana), хранится только в Secret (`htpasswd`, SHA), в
  репозитории нет. Prometheus внутри кластера (Grafana, verify) ходит
  напрямую, без Gateway — не затрагивается.
- **NetworkPolicy в `demo`** (Calico): default deny ingress; разрешено —
  nginx :8080 из `envoy-gateway-system` (прокси) и из `demo` (проверки,
  loadgen), exporter :9113 из `monitoring`.
- **PodDisruptionBudget** `hello`: `minAvailable: 1`.
- **topologySpreadConstraints / anti-affinity** — пропускаем: один узел.
- `verify.sh`: проверочные поды переносятся в namespace `demo` (под
  NetworkPolicy), добавляются проверки: Prometheus через Gateway без
  пароля → 401, с паролем → 200; под из чужого namespace не достучится
  до `hello:80` напрямую; PDB существует.
- Сводка мер безопасности в architecture.md §10 (для README и паспорта):
  non-root, read-only rootfs, drop ALL, seccomp, лимиты, случайные пароли,
  TLS со своим CA, gitleaks в CI, закреплённые версии.

### Не входит

- Kyverno / Trivy (во второй очереди, если останется время);
- mTLS между сервисами (service mesh).

## Технические требования

- `SecurityPolicy.spec.basicAuth.users` → Secret с ключом `.htpasswd`.
  ⚠️ Сверить формат хэша, поддерживаемый Envoy (`{SHA}`).
- NetworkPolicy — стандартный `networking.k8s.io/v1` (Calico её применяет).

## Критерии приёмки

- [x] `prometheus.devops.test` через Gateway: без пароля 401, с паролем 200.
- [x] Под в namespace `default` не получает ответ от `hello.demo:80`;
      через Gateway приложение доступно.
- [x] Prometheus продолжает собирать метрики `hello` (exporter разрешён).
- [x] `kubectl -n demo get pdb hello` — `minAvailable 1`.
- [x] Повторный `deploy.sh` → `changed=0`; CI `e2e` зелёный.

## Проверка

```bash
curl -s -o /dev/null -w '%{http_code}\n' -H "Host: prometheus.devops.test" http://<IP>:30080/
make verify
```

**Отклонения от постановки:**
- **Применение манифестов переделано:** общая роль `kustomize` — сначала
  `kubectl diff` (серверный dry-run), `apply` только при различиях. Причина:
  `kubectl apply` сообщал `configured` для PodDisruptionBudget при каждом
  запуске (воспроизводится на любом PDB — `minAvailable`, `maxUnavailable`,
  процент), хотя `kubectl diff` различий не видел. Теперь признак изменения
  честный для всех каталогов `deploy/*`.
- Для `hello-v2` (1 реплика) PDB не задан: `minAvailable: 1` заблокировал бы
  drain узла.
- Проверочные поды `verify.sh` теперь создаются в namespace `demo` (под
  NetworkPolicy), для проверки блокировки — в `default`.
