# CD-001 — GitOps: непрерывная доставка через Argo CD

| Поле | Значение |
|---|---|
| ID | `CD-001` |
| Статус | `done` |
| Требования | кейс — «CI/CD: развёртывание»; критерии 2, 5; architecture.md §8, §11 |
| Решения | D-08, D-09 |
| Зависимости | SEC-001 (в GitOps уходят уже готовые манифесты) |
| Блокирует | ROLLOUT-001 |

## Цель

Честно закрыть CD: кластер сам забирает изменения из GitHub (pull-модель).
Push в `main` → Argo CD видит новый коммит → синхронизирует кластер.
Pull-модель работает из-за NAT и VPN без входящих подключений — именно
поэтому раньше (CI-001) автодеплой на стенд был отклонён, а теперь он
возможен безопасно. UI Argo CD с деревом ресурсов — через Gateway.

## Архитектура

- `deploy.sh` (Ansible) по-прежнему ставит **платформу**: ОС, kubeadm,
  Calico, cert-manager, Envoy Gateway, мониторинг, логирование, **Argo CD**.
- **Рабочие нагрузки** (`deploy/app`, `deploy/monitoring`, `deploy/logging`,
  `deploy/gateway` — по решению при реализации) описаны как Argo CD
  `Application`, источник — этот репозиторий, путь `deploy/<…>`.
- Ansible создаёт `Application` и ждёт `Synced` + `Healthy` — `deploy.sh`
  остаётся одной командой, `verify.sh` — без изменений по смыслу.
- **Режим без GitOps** сохраняется: `gitops_enabled: false` в `all.yml` →
  применение через `kubectl apply -k`, как сейчас (на случай отсутствия
  доступа к GitHub у эксперта).

## Scope

### Входит

- Helm-чарт Argo CD (минимальная установка: без Dex и ApplicationSet, если
  не нужны; `server.insecure` — TLS терминирует Gateway);
- `HTTPRoute` `argocd.devops.test` (HTTP и HTTPS listener), namespace
  `argocd` с меткой `gateway-access`;
- пароль admin — из Secret, который создаёт Argo CD; команда для его
  получения — в README;
- `Application`(ы): `repoURL` и `targetRevision` — переменные
  (`gitops_repo_url`, по умолчанию `https://github.com/glev23/devops_case.git`;
  `gitops_revision`, по умолчанию `main`); `automated: prune, selfHeal`;
- **CI:** `e2e` передаёт `-e gitops_revision=$GITHUB_SHA` — кластер в CI
  синхронизируется ровно с проверяемым коммитом, а не с `main`;
- метрики Argo CD (ServiceMonitor) и дашборд из чарта, если есть;
- `verify.sh`: Application `Synced/Healthy`, ревизия = ожидаемый коммит;
  UI Argo CD через Gateway отвечает.

### Не входит

- Argo CD Image Updater, ApplicationSet, multi-cluster;
- вебхуки GitHub → Argo CD (нет публичного адреса; опрос раз в 3 минуты —
  по умолчанию, можно сократить `timeout.reconciliation`).

## Критерии приёмки

- [x] С чистой Ubuntu `deploy.sh` ставит Argo CD, приложение приходит из Git;
      `Synced` + `Healthy`.
- [x] Изменение в `deploy/app` после push появляется в кластере без
      запуска `deploy.sh` (на стенде; время до синхронизации записать).
- [x] Ручное изменение в кластере откатывается (selfHeal) — где это не
      мешает ROLLOUT-001.
- [x] `gitops_enabled: false` работает как раньше.
- [x] UI Argo CD открывается через Gateway.
- [x] Повторный `deploy.sh` → `changed=0`; CI `e2e` зелёный на SHA коммита.

## Результат закрытия

Закрыта 02.10.2026.

**Архитектура (как сделано):**
- `deploy.sh` → play «Platform»: cert-manager, Envoy Gateway, kube-prometheus-stack,
  Loki, **Argo CD** — только Helm-чарты и секреты;
- play «Workloads» (роль `workloads`): по одному `Application` на каталог —
  `gateway` → `monitoring` → `logging` → `demo` (`deploy/app`); каждый
  создаётся и ожидается до `Synced` + `Healthy`, затем общие ожидания
  (сертификат, Gateway, Fluentd, приложение);
- `gitops_enabled: false` — те же каталоги через `kubectl diff/apply` из
  локальной копии (роль `kustomize`);
- `syncPolicy`: `automated` (`prune`, `selfHeal`), `retry`; аннотация
  `compare-options: ServerSideDiff=true` — сравнение через серверный dry-run,
  без ложного OutOfSync от значений по умолчанию;
- отслеживание ресурсов — по аннотации (`application.resourceTrackingMethod:
  annotation`), опрос Git — `timeout.reconciliation: 60s`.

**Артефакты:** `helm-values/argo-cd.yaml`, роль `ansible/roles/gitops`, роль
`ansible/roles/workloads` (`defaults`, `tasks/application.yml`,
`templates/application.yaml.j2`), `deploy/argocd/` (HTTPRoute
`argocd.devops.test`), переменные `gitops_*` в `group_vars/all.yml`,
`GITOPS_REVISION`/`GITOPS_REPO_URL` в `.github/workflows/ci.yml`, раздел
«GitOps (Argo CD)» в `scripts/verify.sh`. Роль `app` удалена (её работу
делает `workloads`).

| Проверка | Результат |
|---|---|
| Переход на GitOps на работающем стенде | `failed=0`; Argo CD забрал под управление ресурсы, ранее применённые `kubectl`; повтор — `changed=0` |
| Application | `demo`, `gateway`, `logging`, `monitoring` — `Synced` / `Healthy` |
| Self-heal | `kubectl scale deploy/hello --replicas=5` → через ~2 с снова 2 |
| Push → кластер | push коммита `aa4e5b6` в 11:02:08 → в 11:03:40 кластер на стенде синхронизирован с ним, изменение `deploy/app/loadgen.yaml` применено **без `deploy.sh`** (~1,5 мин) |
| UI | `argocd.devops.test` через Gateway, `/healthz` → `ok` |
| CI, чистая установка | Argo CD синхронизирован ровно с проверяемым коммитом `aa4e5b6`; повтор `changed=0`; все проверки — [run 36981766024](https://github.com/glev23/devops_case/actions/runs/36981766024), e2e 7 мин 17 с |
| `gitops_enabled: false` с нуля | OK — с чистой Ubuntu `deploy.sh -e gitops_enabled=false`: `failed=0` за 509 с, повтор `changed=0`, Argo CD не установлен, `verify.sh` — все проверки пройдены |

**Отклонения от постановки:**
- UI Argo CD через Gateway — как и Grafana, только по hostname
  (`argocd.devops.test`), для браузера нужна запись в hosts.
- ServiceMonitor'ы Argo CD включены в values; отдельный дашборд Argo CD не
  добавлялся.
- Найдено попутно: локальная цепочка линтеров маскировала код выхода
  ansible-lint (`| tail`), из-за чего замечание `name[template]` не было видно
  локально; имена задач исправлены, линтер теперь запускается без пайпа.
