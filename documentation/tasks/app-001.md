## Цель

В кластере работает nginx, который на HTTP-запрос отвечает однозначно
проверяемой строкой `Hello World! from <имя пода>` и пишет access-лог в
JSON в stdout, готовый к сбору Fluentd. Приложение ставится тем же
`sudo ./deploy.sh`.

## Scope

### Входит

- Kustomize-каталог `deploy/app/`: Namespace `demo`, ConfigMap с
  `nginx.conf`, Deployment (2 реплики), Service `hello` (ClusterIP, порт 80);
- ответ `Hello World! from $hostname` (`text/plain`) на `/`;
- `/healthz` для probes (без записи в access-лог);
- access-лог в JSON (время, метод, путь с query, код, байты, длительность,
  IP клиента, `X-Forwarded-For`, `X-Request-Id`, user-agent, имя пода) в
  stdout, error-лог в stderr;
- `stub_status` на отдельном порту 8081 — задел для nginx-exporter (MON-001);
- базовая безопасность: non-root, read-only rootfs, drop ALL capabilities,
  seccomp `RuntimeDefault`, requests/limits, readiness/liveness probes;
- Ansible-роль `app`: `kubectl apply -k` + ожидание rollout; повтор без
  изменений даёт `changed=0`.

### Не входит

- доступ снаружи кластера (GW-001);
- экспортер метрик и ServiceMonitor (MON-001);
- второй backend `v2` и маршрут с кодом 500 (GW-002);
- PodDisruptionBudget, NetworkPolicy (SEC-001).

## Критерии приёмки

- [x] `sudo ./deploy.sh` разворачивает приложение, обе реплики `Ready`.
- [x] Запрос из пода в кластере к `http://hello.demo/` → `200`,
      тело `Hello World! from hello-…`.
- [x] Ответы приходят от обеих реплик (балансировка Service).
- [x] В `kubectl logs` — JSON-строка с этим запросом, включая query-метку.
- [x] Неизвестный путь → `404`, запись в логе с `"status":404`.
- [x] Контейнер работает не от root (`id` → uid 101).
- [x] Повторный `sudo ./deploy.sh` → `changed=0`.

## Проверка

```bash
kubectl -n demo get deploy,pods,svc
kubectl run curl --rm -i --restart=Never --image=curlimages/curl:8.16.0 -- \
  sh -c 'for i in 1 2 3 4; do curl -s "http://hello.demo/?trace=app001-$i"; done'
kubectl -n demo logs -l app.kubernetes.io/name=hello --tail=4
```

## Результат закрытия

Закрыта 30.09.2026.

**Артефакты:** `deploy/app/{kustomization.yaml,namespace.yaml,deployment.yaml,service.yaml,nginx.conf}`,
роль `ansible/roles/app`, переменная `repo_root` в `group_vars/all.yml`,
play «Workloads» в `site.yml`.

**Фактические проверки** (VM `k8s` со снимка `cluster-ready-v2`):

| Проверка | Результат |
|---|---|
| Прогон `deploy.sh` | `changed=1` (только применение приложения), повтор — `changed=0` |
| Поды | `hello` 2/2 `Ready`, образ `nginxinc/nginx-unprivileged:1.30.5-alpine` |
| 6 запросов `curl http://hello.demo/?trace=app001-N` | `Hello World! from hello-…-dtwrn` / `…-lpksr` — обе реплики |
| Access-лог | JSON: `"uri":"/?trace=app001-1"`, `"request_id":"req-1"`, `"status":200`, `"pod":"hello-…"` |
| `/nope` | `404`, в логе `"status":404` |
| Заголовки | `200 OK`, `Content-Type: text/plain`, `Server: nginx` (без версии) |
| `:8081/stub_status` | `Active connections`, счётчики запросов |
| `id` в контейнере | `uid=101(nginx)` |

**Отклонения от постановки:** нет. Замечание по проверке: у
`kubectl run -i` иногда теряется конец вывода (гонка при подключении к
поду), поэтому надёжнее запускать проверочный под без `-i` и читать
`kubectl logs`. Так же будет сделан `make verify` (AUTO-001).

**Follow-up:** GW-001, LOG-001 разблокированы.
